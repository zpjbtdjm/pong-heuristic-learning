## 优化历史
- **Turn 0** 我要求模型进行 3 次提升，以验证模型是否能够正常迭代。
- **Turn 3** 我又要求模型额外进行 3 次提升，以进一步测试其迭代能力。
- **Turn 4** 模型优化受阻，并尝试自行进行大量参数搜索；我制止了这一行为，并要求模型做出实质性改动，而不是仅停留在参数调整上。
- **Turn 12** 由于长期自我优化失败，模型出现早停现象；我重新启动模型，并要求其必须持续迭代直到我手动终止。
- **Turn 13** 模型自动识别并启动 `/goal` 模式。
- **Turn 35** 由于多个轮次的表现长期徘徊在 -1.00 到 -0.90 左右，我要求模型进行大规模方向搜索；这次转向取得了显著效果。
- **Turn 38** 模型自行识别出 state 中缺失拍速信息，并主动补充该信息；这一补充在后续搜索中产生了显著效果。
- **Turn 55** 模型发现只剩一局失败后，自动扩大分析范围，先查看该局末端的失败情况，再决定是否继续调整。
- **Turn 59** 模型自行读取所有局数的内容，分析真正的失分点，并发现这些失分点很难归纳为同一类模式。
- **Turn 65** 模型尝试对特殊局数进行针对性处理，但这一做法类似某种 hacking，并不合理，因此被我拒绝；同时模型又逐渐进入调参模式，似乎在接近上下文长度限制时更容易出现这种现象。
- **Turn 68** 模型持续尝试修改新的 state 以获取更多信息，但这些信息实际上并无帮助，因此被我制止。

## 决策过程
1. 人类手动引导且取得效果的决策，共 **1** 次：
   - 要求模型搜索更多方向。

2. 合理且取得效果的模型决策，共 **3** 次：
   - 自动识别并启动 `/goal` 模式；
   - 自行识别出 state 中缺失拍速信息；
   - 自行扩大分析范围。

3. 错误的模型决策，后被人类手动修正，共 **4** 次：
   - 试图自行进行大量参数搜索；
   - 自行出现早停；
   - 尝试对特殊局数进行针对性处理；
   - 持续尝试修改新的 state。

## 教训
- **时间审计**：模型缺乏时间审计能力，可能会启动执行时间过长的任务，例如大规模参数搜索。
- **思维定式**：当上下文过长时，模型容易陷入局部思维定式，导致策略过早收敛，最终退化为调参，难以继续进行有效搜索。
- **任务漂移**：在清空上下文后，模型对任务边界的理解可能出现漂移，从而产生一些误解可行方案的 hacking 策略。

## 启发
- **共同优化**：在优化目标策略的过程中，模型的行为并非固定不变；它可能通过自我设定目标、补充缺失信息、扩大分析范围等方式，主动调整并优化自身的优化过程。
